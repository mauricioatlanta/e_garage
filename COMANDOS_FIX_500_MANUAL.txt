========================================
COMANDOS PARA EJECUTAR EN EL SERVIDOR
========================================

Copia y pega estos comandos UNO POR UNO en tu servidor Linux (SSH).


------------------------------------------------------------
PASO 1: Limpiar y Corregir settings_prod.py
------------------------------------------------------------

# Backup
cp /srv/egarage/gestion_taller/settings_prod.py /srv/egarage/gestion_taller/settings_prod.py.backup.$(date +%Y%m%d_%H%M%S)

# Limpiar caracteres invisibles de Windows (CRLF -> LF)
sed -i 's/\r//' /srv/egarage/gestion_taller/settings_prod.py

# Quitar la carpeta /app/ inexistente de las rutas
sed -i 's|/srv/egarage/app/|/srv/egarage/|g' /srv/egarage/gestion_taller/settings_prod.py

# Eliminar bloque anterior si existe
sed -i '/# --- FIX FINAL MANUAL ---/,$d' /srv/egarage/gestion_taller/settings_prod.py

# Agregar configuración de emergencia al final
cat >> /srv/egarage/gestion_taller/settings_prod.py << 'EOF'

# --- FIX FINAL MANUAL ---
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": "/srv/egarage/db.sqlite3",
    }
}
SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')
CSRF_TRUSTED_ORIGINS = ["https://egarage.cl", "https://www.egarage.cl"]
EOF


------------------------------------------------------------
PASO 2: Verificar Servicio de Gunicorn
------------------------------------------------------------

# Ver el contenido del servicio
cat /etc/systemd/system/gunicorn.service

# Si la línea ExecStart NO termina con "gestion_taller.settings_prod:application",
# edita el archivo:
# sudo nano /etc/systemd/system/gunicorn.service
# 
# Y cambia la línea ExecStart para que termine con:
# gestion_taller.settings_prod:application


------------------------------------------------------------
PASO 3: Reinicio de Limpieza Total
------------------------------------------------------------

# 1. Permisos de dueño para el usuario del servidor web
sudo chown -R www-data:www-data /srv/egarage
sudo chmod 664 /srv/egarage/db.sqlite3

# 2. Recolectar archivos estáticos (CSS/JS)
/srv/egarage/venv/bin/python /srv/egarage/manage.py collectstatic --noinput

# 3. Reiniciar el motor
sudo systemctl daemon-reload
sudo systemctl restart gunicorn
sudo systemctl restart nginx


------------------------------------------------------------
VERIFICACIÓN
------------------------------------------------------------

# Refresca https://www.egarage.cl

# Si el Error 500 persiste, ejecuta esto para ver los logs en tiempo real:
sudo journalctl -u gunicorn -f

# (Presiona Ctrl+C para salir)


------------------------------------------------------------
NOTAS
------------------------------------------------------------

- El script elimina los caracteres CRLF (Windows) que causan el error $'\r': command not found
- Corrige las rutas que tienen "/app/" de más
- Fuerza la configuración de SQLite y desactiva el bloqueo
- Ajusta permisos y recolecta archivos estáticos
- Reinicia todos los servicios en el orden correcto
